# Explainer Video Builder V2 产品化设计

## 目标

把已经通过验收的精剪、科研汇报主题、配音字幕和自动验证能力，从一次性项目脚本沉淀为可复用的 `explainer-video-builder-skill V2` 支线。V2 同时支持：

- `enhance`：读取已有视频或录屏素材，按新时间轴删除、压缩、重排并补充信息卡；
- `create`：从 PPT 导出页、图片和视频素材开始，按同一套时间轴生成完整讲解视频。

工作只在 `v2-enhance-showcase` 分支进行。GitHub `main` 保持不变，是否合并由用户单独决定。

## 成功标准

1. 项目内容不再硬编码在 Python 构建器中，改由 JSON 项目清单驱动。
2. 汽车 RAG 项目可由通用 CLI 复现当前 72 秒科研汇报风格成片。
3. 6G 喷泉码项目可使用同一 CLI 和主题生成第二个跨主题样片。
4. 多音字和断词通过项目级纠音词典统一改写，配音和字幕共用改写后的文本。
5. 自动检查覆盖时间轴、字幕安全区、防抖渲染、黑帧、音频削波、规格和关键帧。
6. 所有原始素材只读引用，生成物写入项目指定输出目录。

## 总体架构

V2 使用一份 JSON 项目清单作为唯一输入。CLI 加载清单、完成纠音改写、验证时间轴和模板字段，再依次调用卡片渲染、视频片段构建、TTS、ASS 字幕、确定性混音、最终合成和验证模块。

```text
project.json
  -> manifest.py       结构与时间轴验证
  -> pronunciation.py 配音/字幕统一改写
  -> themes.py         主题令牌
  -> cards.py          数据驱动卡片模板
  -> media.py          clip/image/card 片段与 concat
  -> audio.py          TTS、字幕、numpy 混音
  -> verify.py         规格、黑帧、响度、抽帧检查
  -> cli.py            validate/build/verify
```

## 项目清单契约

顶层字段：

- `version`: 固定为 `2`；
- `mode`: `create` 或 `enhance`；
- `theme`: 首个正式主题为 `research_ppt`；
- `duration`, `fps`, `width`, `height`；
- `output_dir`, `output_name`；
- `pronunciations`: 项目级替换表，覆盖内置纠音；
- `visuals`: 连续覆盖全片的画面段；
- `narration`: 带起止限制的旁白段；
- `verification`: 关键帧抽样时间和允许误差。

画面段支持：

- `card`：使用数据驱动模板；
- `clip`：截取已有视频，可通过 `source_duration / output_duration` 压缩；
- `image`：使用 PPT 导出页或用户图片生成静态片段。

首批卡片模板：

- `hero`
- `process`
- `metric_compare`
- `chapter`
- `metric_grid`
- `ending`

## 模式边界

`create` 与 `enhance` 共用同一渲染、配音、字幕、混音和验证流水线，仅在输入约束上不同：

- `enhance` 至少包含一个 `clip` 段，以真实已有视频为主要证据；
- `create` 可完全由 `card` 和 `image` 构成，也可插入短视频素材；
- 用户未明确授权剪辑时，默认走原 Skill 的保时长增强流程；只有项目清单明确写为 V2 且配置新时间轴时，才允许删除、压缩和重排镜头。

## 科研汇报主题

`research_ppt` 提取用户 6G PPT 的稳定视觉特征，而不复制高密度申报书版面：

- 白底；
- 政务蓝页眉、标题线和结论条；
- 红色只标关键提升、风险或对比箭头；
- 黄色只用于栏目编号和结论引导词；
- 结论条底边不超过 y875，y900 以下留给字幕；
- 真实录屏标签固定右上安全区。

## 纠音策略

内置替换表至少包括：

- `重排` -> `重新排序`
- `重传` -> `重新传输`
- `多运营商` -> `多家运营商`

改写在 TTS 和字幕分流之前执行，因此二者文本始终一致。项目清单可增加或覆盖替换。验证器禁止改写后文本仍包含被禁用词。

## 两个验收案例

### 案例 A：汽车 RAG

- 模式：`enhance`
- 时长：72 秒
- 主题：`research_ppt`
- 证据：四道真实题和三个泛化知识点录屏
- 目标：通用 V2 构建结果与已验收 PPT 风格修正版一致

### 案例 B：6G 喷泉码与多路聚合

- 模式：`create`
- 时长：30 秒
- 主题：`research_ppt`
- 素材：用户提供的 6G PPT 导出页
- 结构：标题 -> 背景痛点 -> 三项研究内容 -> 预期指标 -> 结束
- 目标：证明同一主题和流水线不依赖汽车 RAG 的字段、指标或素材路径
- 隐私边界：PPT 导出页、本地项目清单和成片只写入用户交付目录，不提交到 Git；仓库仅保留不含用户内容的中性 `create` 示例

## 验证与交付

- 单元测试验证清单、模式约束、纠音、模板字段和字幕安全区；
- 汽车 RAG 案例进行完整 72 秒构建；
- 6G 案例进行完整 30 秒构建；
- 每个成片执行 ffprobe、blackdetect、volumedetect 和关键帧接触表检查；
- 分支工作区和 `main` 均保持干净后交付；
- 不自动合并或推送 `main`。
