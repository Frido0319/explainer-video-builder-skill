# Explainer Video Builder V1 / V2 双版本选择设计

## 目标

让 `explainer-video-builder-skill` 在同一个 skill 中长期保留 V1 与 V2，用户可以明确选择版本，未明确选择时也能按安全规则自动路由。V2 不替换 V1，V1 的既有默认行为和脚本保持可用。

## 选择方案

采用“单 skill、双实现、主指令路由”的结构：

- `V1（保真增强）`：处理已有视频，保持原画面、顺序和总时长，只叠加中文配音、中文字幕和 BGM。
- `V2（制作/精剪）`：使用 `project.json` 和 `explainer_video_v2` 引擎；其中 `create` 从 PPT、图片、文案和素材创建视频，`enhance` 在明确授权后删除、压缩、重新排序或补充已有画面。
- 用户可在请求中直接说“用 V1”或“用 V2”；显式选择永远优先。
- 未显式选择时，已有视频且未授权剪辑走 V1；从素材新建、或明确授权改变镜头结构时走 V2；仍无法判断时走 V1。
- 每次执行前必须向用户复述本次选择的版本和边界，防止把自动路由误解为剪辑授权。

不采用两个独立 skill：这会造成触发竞争、公共规则重复和版本漂移。不采用把 V1 强行包装为 V2 manifest：V1 已有脚本经过实战验证，重写会增加回归风险。

## 仓库结构

`SKILL.md` 顶部增加版本路由，作为唯一权威选择规则。V1 继续使用 `scripts/` 和现有 `references/`；V2 继续使用 `explainer_video_v2/`、`examples/` 和 V2 manifest。README 同步给人类用户展示相同入口，`evals/evals.json` 增加显式 V1、显式 V2 和默认回退用例。

不增加统一包装 CLI。skill 的版本选择发生在任务路由层；选中 V1 后运行既有脚本，选中 V2 后运行 `python3 -m explainer_video_v2.cli`。这样既让两套能力可选择，也避免制造一个没有真实统一参数模型的薄壳命令。

## 行为契约

路由优先级固定为：

1. 显式版本：用户说 V1 或 V2。
2. 明确意图：保留原片只叠加走 V1；新建或授权结构化剪辑走 V2。
3. 安全回退：V1。

选择 V2 后必须继续选择：

- `create`：从零建立时间轴；
- `enhance`：至少包含一个已有视频 `clip`，且必须有剪辑授权。

用户显式选择与任务冲突时不得静默改版本。例如用户说 V1 又要求删除镜头，应说明 V1 不允许该操作，保留 V1 边界；只有用户改选 V2 才执行剪辑。

## 兼容与安全

- V1 的 `scripts/make_tts.py`、`make_subs.py`、`mix_audio.py`、`verify_video.py` 和既有参考文档不删除、不改名。
- V2 的 manifest schema 仍固定 `version=2`，不引入含义冲突的 `version=1` manifest。
- 所有素材只读，输出写入独立目录。
- 未获剪辑授权时，任何自动判断都不能进入 V2 `enhance`。
- 本次只做本地分支和本地 main 集成，不自动推送 GitHub。

## 验证

新增版本契约测试，检查：

- SKILL 与 README 同时声明 V1、V2、默认 V1 和显式选择优先；
- V1 关键脚本仍存在；
- V2 CLI 与两个模式仍存在；
- evals 覆盖显式 V1、显式 V2、无版本安全回退。

然后运行完整单元测试，以及 V2 `create` 和汽车 RAG `enhance` 的真实验收。合并到本地 main 后再重复完整测试，确认双版本共存。
