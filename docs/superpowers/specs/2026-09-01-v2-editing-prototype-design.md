# V2 精剪能力原型设计

## 目标

在不修改 GitHub `main` 稳定版的前提下，于 `v2-prototype-editing` 支线制作一个可直接观看和比较的精剪原型，验证 `explainer-video-builder-skill` 从“配音、字幕、BGM 增强”扩展到“画面节奏与视觉聚焦优化”的可行性。

本原型同时为未来的两种正式模式建立共同基础：

- `create`：从 PPT、报告和素材生成全新技术讲解视频。
- `enhance`：对已有视频进行画面、配音、字幕、BGM和节奏优化。

本阶段只验证 `enhance` 的新增画面精剪能力，不重构完整生产流程。

## 输入与输出

输入视频只读引用：

`${AUTOMOTIVE_RAG_DELIVERY}/驭远智擎_发动机与电动汽车专属RAG对比_最终版.mp4`

参考音频与字幕来源：

`${AUTOMOTIVE_RAG_DELIVERY}/optimize29/驭远智擎_发动机与电动汽车专属RAG对比_配音字幕版.mp4`

原型范围选择原视频 `36.0s–64.0s`，总时长固定为 `28.0s`。该区间同时包含四题对比总结和泛化能力测试开场，能够展示数据强调、章节衔接和页面聚焦三类能力。

输出目录：

`${AUTOMOTIVE_RAG_DELIVERY}/v2_prototype/`

输出两个文件：

- `原版片段_36-64s.mp4`：直接截取现有配音字幕版，作为基线。
- `V2精剪样片_36-64s.mp4`：加入新增视觉剪辑能力的样片。

## 精剪设计

### 1. 章节衔接

在 `52.0s` 原始时间点，也就是样片内 `16.0s`，加入时长约 `0.8s` 的章节提示：“泛化能力测试”。提示采用半透明深蓝色横向标签，不覆盖页面主体数据，进入和退出使用短淡化，避免花哨转场。

### 2. 动态聚焦

对静态或信息密集页面使用缓慢、克制的数字推近：

- 样片 `0.0s–8.0s`：保持全景，让观众建立页面结构。
- 样片 `8.0s–16.0s`：轻微推近四题对比结果区，最大缩放不超过 `1.08×`。
- 样片 `16.0s–21.0s`：章节切换后恢复全景。
- 样片 `21.0s–28.0s`：轻微推近泛化测试方法和结果区域，最大缩放不超过 `1.06×`。

所有缩放保持 1920×1080 输出，不改变源内容比例，不裁掉关键标题、数字或出处。

### 3. 关键数据强调

在不改动原始数据的前提下增加两组视觉标注：

- 四题分析页：强调“命中率更高”和“带教材出处”。
- 泛化测试页：强调“不同问法”和“稳定命中”。

标注形式为细边框圆角标签与短引导线，配色沿用现有蓝绿风格。标注出现时间与旁白内容同步，每组停留约 2–3 秒；不得遮挡原文字、原图表和中文字幕。

### 4. 音频与字幕

原型直接复用已经验证过的配音字幕版对应区间，不重新生成旁白，不修改语速，不更换 BGM。视觉精剪必须避开现有字幕区域，确保这次比较只反映新增画面剪辑能力。

## 实现边界

- GitHub `main` 保持不变，所有设计、脚本和提交只存在于 `v2-prototype-editing` 支线。
- 不修改任何原始视频、PPT、报告和已有成片。
- 不接入 MiniMax，不生成虚构实验镜头，不增加无法由原片或权威文档支持的数据。
- 不建设批量发布、账号管理或营销模块。
- 本阶段不把 `create` 和 `enhance` 完整重构成统一 CLI；只通过原型验证共享的时间轴、视觉聚焦和验证思路。

## 工程结构

支线新增原型脚本和配置：

- `prototypes/v2_editing/timeline.json`：28秒样片的时间轴、缩放和标注定义，作为唯一配置来源。
- `prototypes/v2_editing/build_prototype.py`：读取时间轴，调用 ffmpeg 构建基线片段与精剪样片。
- `prototypes/v2_editing/verify_prototype.py`：验证时长、分辨率、音轨、字幕安全区和关键帧变化。
- `tests/test_v2_timeline.py`：验证时间轴边界、缩放上限、标注文本和输出时长。

脚本不依赖云服务，兼容本机 ffmpeg 4.2.7 和 Python 环境。

## 验收标准

- 两个输出文件均为 `1920×1080`、H.264 + AAC，可正常播放。
- 两个文件时长均为 `28.0s ± 0.10s`。
- 精剪版音频与基线版来自同一区间，听感与字幕内容一致。
- 精剪版至少包含两段动态聚焦、一个章节提示和两组数据强调。
- 最大缩放不超过 `1.08×`，不裁掉关键标题、指标或出处。
- 所有新增标注位于字幕安全区上方，不遮挡原字幕。
- 在代表时间点抽帧并视觉检查，能明显看出精剪版的视觉引导，同时保持正式技术汇报风格。
- `git diff main...v2-prototype-editing` 不包含对现有稳定脚本的修改。

## 后续演进

原型通过后再分成两个独立实施阶段：

1. 提取通用 `timeline.json` 模型和画面分析器，落地 `enhance` 正式模式。
2. 让 `create` 复用相同时间轴、视觉组件和验证器，实现两种模式共享底层但保持入口清晰。
