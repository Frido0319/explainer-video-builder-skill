# Explainer Video Builder 用户可见版本菜单设计

## 目标

让 `explainer-video-builder-skill` 在用户没有指定版本时，主动列出 V1、V2 create、V2 enhance 三个可选方向，说明差异、给出推荐理由，并等待用户选择。版本决定不再只发生在 skill 内部。

## 用户菜单

未检测到明确版本时，先输出以下菜单，不得开始制作或修改素材：

```text
请选择视频制作方向：

1. V1｜保真增强
   保留原画面、顺序和时长，只添加配音、字幕和 BGM

2. V2 create｜重新制作
   根据 PPT、图片、文案和素材，从零制作讲解视频

3. V2 enhance｜精剪重构
   可删除、压缩、重新排序原视频，并增加标题卡、数据卡等新画面

根据你的素材和目标，我推荐：<选项>
推荐理由：<一句与当前请求直接相关的理由>
请回复 1、2、3，或直接回复 V1、V2 create、V2 enhance
```

菜单中的版本名称、三项核心边界和回复格式固定；推荐项与推荐理由根据用户请求填写。

## 路由规则

1. 用户明确说 `V1`、`V2 create` 或 `V2 enhance` 时，复述所选方向和行为边界后直接执行，不重复展示菜单。
2. 用户只说 `V2`、但未说明 `create` 或 `enhance` 时，列出两个 V2 子方向并等待选择。
3. 用户没有指定版本时，展示完整三项菜单并等待选择；不得静默默认 V1，也不得按推荐项自动开工。
4. 用户回复 `1/2/3` 时，分别映射到 `V1 / V2 create / V2 enhance`。
5. 用户的选择与请求冲突时，说明冲突并停在版本边界，不能静默切换。例如选择 V1 又要求删除镜头时，应说明该操作需要 V2 enhance。
6. `V2 enhance` 除版本选择外还必须有明确剪辑授权。菜单第 3 项本身已经说明可执行的剪辑动作；用户选择第 3 项视为对这些动作的授权，超出菜单范围的破坏性操作仍需单独确认。

## 推荐规则

- 已有成片，只要求配音、字幕、BGM或强调不改时长：推荐 V1。
- 主要输入是 PPT、图片、报告、文案，目标是重新制作：推荐 V2 create。
- 已有视频，用户希望删减、压缩、重新排序、重构节奏或补充新画面：推荐 V2 enhance。
- 信息不足时可以推荐 V1 作为保守方向，但仍必须等待用户选择。

推荐只能帮助决策，不能替代用户选择。

## 文件改动

- `SKILL.md`：把现有自动路由规则改成用户可见菜单与等待规则，作为权威行为契约。
- `README.md`：同步菜单、选择示例和“不再静默默认”的说明。
- `evals/evals.json`：增加未指定版本、只说 V2、数字回复和已明确版本四类用例。
- `tests/test_version_selection.py`：将旧的“默认 V1”断言改为菜单契约，验证菜单文案、等待规则、映射规则和 eval 覆盖。

不修改 V1 媒体脚本、V2 manifest schema、渲染器、TTS、字幕、混音和成片验收逻辑。

## 验收标准

1. SKILL 与 README 都包含同一组 V1、V2 create、V2 enhance 选择方向。
2. 未指定版本时明确要求“展示菜单并等待用户选择”，不再出现“默认使用 V1”。
3. 用户只说 V2 时，必须进一步选择 create 或 enhance。
4. 用户已明确版本时不重复询问。
5. `1/2/3` 映射写明且由测试保护。
6. 完整单元测试、skill 结构校验、V2 create 和汽车 V2 enhance 验收继续通过。
7. 修改先在 `v2-enhance-showcase` 支线完成；通过后合入本地 main，不推送 GitHub。
